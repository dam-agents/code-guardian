# Visual PR artifact

Read this file when the worklist has a non-empty `artifacts_due`. Each entry is
`{number, action}`:

- **`action: "retry_unassign"`** — the artifact exists (the PR's history file
  carries an `<!-- artifact-gist: … -->` **or** `<!-- artifact-dam: … -->`
  marker) but the bot is still assigned, because a previous unassign failed.
  Retry the unassign (step 5), log the outcome, generate nothing. Either marker
  is the idempotency guard against re-publish churn.
- **`action: "generate"`** — run the full procedure below.

Artifacts are generated by the configured `$ARTIFACT_SKILL`, installed by
preflight from its `@<owner/repo>` source. `artifact_skill: none`/missing → the
feature is off entirely. Preflight evaluated the **assignee gate**
(`$BOT_LOGIN` assigned to the PR) across every open non-draft PR.

**Where it publishes** is set by `artifact_targets` (default `gist`). The one
on-disk HTML is published to each listed surface:

- **`gist`** — a secret gist on the target repo's host, available **only when
  that host is `github.com`**: the rendered link goes through an external
  renderer that cannot reach another host, and a review's artifact never
  crosses to a different host ([runbook.md](runbook.md) → **Hard
  invariants**). Elsewhere preflight drops `gist`, and with no surface left the
  feature is off for the run (the weekly audit reports it as
  `artifact_targets`).
- **`dam`** — the platform's DAM Artifact Library, published via the per-agent
  MCP tools (`create_artifact_upload_url` + `create_artifact`), registered only
  under the owner's **"artifact library" experimental flag**. `dam` is
  therefore always **best-effort**: tools not registered, or any DAM sub-step
  erroring → log and continue with whatever else is listed. A missing DAM
  surface never fails the artifact step or the run.

> ⚠️ **Publishes to a public surface.** A "secret" gist is unlisted, not
> private, and a `visibility:"public"` DAM artifact is reachable by anyone with
> its `shareUrl` — the unguessable slug is the only access control. That is
> intended, and gated behind the explicit human assignment of `$BOT_LOGIN`.

## Procedure (per `generate` entry)

1. **Generate** — invoke `$ARTIFACT_SKILL` with the PR number, plus `$PR_DIR`
   when the PR was reviewed this run and the skill's `SKILL.md` accepts it
   (otherwise the skill works via `gh` from the number). Save the single
   self-contained HTML to `work/reviews/pr-artifacts/pr-<n>.html` (`mkdir -p`
   first). Skill error → log `skipped (skill-errored)` and stop this PR: no
   publish, no comment, no unassign.
2. **Publish — each target in `$ARTIFACT_TARGETS`, independently; at least one
   attempted target must succeed.** Reuse the one on-disk `pr-<n>.html`, never
   rebuild between surfaces.
   - **a. Gist** (only with `gist` in `$ARTIFACT_TARGETS` and `$REPO_HOST` =
     `github.com`):
     `GIST_URL=$(gh gist create work/reviews/pr-artifacts/pr-<n>.html --desc "PR #<n> review artifact")`,
     then `GIST_ID=$(basename "$GIST_URL")`. Never pass `--public`. On failure,
     log `PR #<n>: gist publish failed (<reason>)`, leave `GIST_ID` empty, and
     continue to (b).
   - **b. DAM Artifact Library** (only with `dam` in `$ARTIFACT_TARGETS`;
     best-effort, feature-gated): publish the **same** HTML via the MCP tools.
     Tools not registered this session → skip straight to logging, not an
     error.
     1. `create_artifact_upload_url {file_name: "pr-<n>.html"}` →
        `{url, uploadRef}`.
     2. `curl -sS -f -X PUT -H 'Content-Type: text/html' --data-binary @work/reviews/pr-artifacts/pr-<n>.html '<url>'`
        — the explicit content type keeps the stored MIME correct; the viewer
        renders on `type:"html"` regardless.
     3. `create_artifact {title: "PR #<n> review artifact", upload_ref: "<uploadRef>", type: "html", visibility: "public"}`
        → capture `shareUrl` as `DAM_URL` and `id` as `DAM_ID`.

     A missing tool or any error at any sub-step: log
     `PR #<n>: DAM artifact publish skipped (<reason>)`, leave
     `DAM_URL`/`DAM_ID` empty, continue. Never fail the run over the DAM half.
   - **No attempted target succeeded** → treat the step as `skill-errored`:
     post no comment, write no marker, keep `$BOT_LOGIN` assigned for a later
     retry, log, and stop this PR here.
3. **Comment the surviving link(s)** in a **single** PR comment, including only
   the surfaces that succeeded (gist first, then DAM):

   ```bash
   gh pr comment <n> --repo "$REPO" --body "📊 **PR #<n> review artifact** — [gist](https://htmlpreview.github.io/?https://gist.githubusercontent.com/$BOT_LOGIN/<GIST_ID>/raw/pr-<n>.html) · [DAM Artifact Library](<DAM_URL>)"
   ```

   Drop the segment of a surface that was skipped or failed. One comment, never
   two.
4. **Record the ids** in `reviews/pr-<n>.md` right after the title heading,
   each on its own line, overwriting existing markers in place (pruning reads
   both): `<!-- artifact-gist: <GIST_ID> -->` and
   `<!-- artifact-dam: <DAM_ID> -->`. Omit the line of a surface that was not
   published.
5. **Unassign** — prefer REST, because `gh pr edit` goes through GraphQL, which
   401s in this pod:

   ```bash
   gh api -X DELETE "repos/$REPO/issues/<n>/assignees" -f "assignees[]=$BOT_LOGIN" >/dev/null \
     || gh pr edit <n> --repo "$REPO" --remove-assignee "$BOT_LOGIN"
   ```

   A failed unassign is logged, not fatal: next run preflight emits a
   `retry_unassign` entry.
6. **Audit line (mandatory)** —
   `PR #<n>: <artifact_skill> ran → gist <GIST_ID> + DAM <DAM_ID>`, naming only
   the surfaces that succeeded (for example
   `→ gist <GIST_ID> (DAM skipped: flag off)`), or
   `PR #<n>: <artifact_skill> skipped (<install-failed|skill-errored>)`.

The saved HTML is persisted `work/` state. It, the gist and the DAM artifact
are deleted by the prune step when the PR closes ([review.md](review.md) →
**Pruning**).
