# Project profile — `work/PROFILE.md`

Read this file when the worklist carries a `profile` object, when a review
brief needs the repository map, or when the operator asks about the profile.

The profile is a **map of the reviewed repository** — where things are and what
the repository declares about itself — generated by `scripts/profile.sh` from
the default branch and kept current by a structural fingerprint. It replaces
the orientation every review and every skill subagent used to rebuild from
`ls-tree` and `grep`.

## What it is, and is not

- **Orientation, never evidence.** A finding is anchored in the diff and
  verified against the surrounding code in the clone ([review.md](review.md) →
  **Criteria & review style**); the profile only says where to look. No finding
  cites the profile or the history section.
- **Declared, never inferred.** Every row is lifted from something the
  repository states — a manifest field, a README heading, doc front matter, a
  CODEOWNERS line — and carries its source path in `src`. The one judgement
  layer is the agent-owned notes file, kept separate.
- **Complete or explicit.** A capped section says what it left out in the
  header's `truncated` line; an absent section means its detector found nothing
  (a repo without ADRs has no `## Decisions`).

## Sections and their detectors

| Section | Derived from |
| --- | --- |
| `## Modules` | Manifests at any depth (`package.json` incl. workspaces, `pnpm-workspace.yaml`, `go.mod`/`go.work`, `Cargo.toml`, `pyproject.toml`/`setup.cfg`, `pom.xml`/`build.gradle*`, `*.csproj`, `composer.json`, `Gemfile`), one module per directory; `role` = the manifest's description, else the module README's first heading and sentence. |
| `## Docs` | `*.md` under `docs/`, `doc/`, `documentation/`, `wiki/`: title, freshness stamp (front matter `last_verified`/`updated`/`date`, a `Last verified:` line, else `blob:<sha>`), and the code paths the page covers — front matter (`paths`, `scope`, `subsystem`, `module`, `components`), else path mentions in the text that exist in the tree, else a basename ↔ module-name match; `via` names the rule that fired. |
| `## Decisions` | Files in `adr*`, `decisions`, `rfcs` directories: id, title, status (front matter or the `## Status` section), scope, date. |
| `## Conventions` | The repository's own agent and contributor instructions — `CLAUDE.md`, `AGENTS.md`, `CONTRIBUTING.md`, `.cursorrules`, Copilot instructions — copied verbatim up to 12 kB total. |
| `## Ownership` | `CODEOWNERS` rules. |
| `## Checks` | `.github/workflows/*` (name, triggers) and the default branch's required status checks. |
| `## Noise` | Globs never reviewed as code: built-in lockfile / snapshot / build / vendored / minified / generated patterns plus `.gitattributes` `linguist-generated` and `linguist-vendored` entries. Classifies every changed file of a PR. |
| `## History` | The agent's own posted reviews (`work/reviews/pr-*.md` → `findings-json`, last 90 days): per directory the open critical/warning/suggestion counts, `still`-present findings, last date, sample summaries, plus the recurring finding classes. Recomputed on every refresh — a record of the past, not a claim about the code. |
| `## Notes` | Rows of `work/PROFILE-NOTES.md`, each stamped with the blob of its source and a status (`new`, `current`, `stale`, `orphan`, `unanchored`). |

Data lives in `work/PROFILE.json`; `work/PROFILE.md` is its render for readers.
Both are runtime state, backed up with `work/`.

## Freshness

The header carries `base` (the SHA the profile was generated at), `verified`
(the newest SHA whose structure matched it), `generated`, `fingerprint`, `mode`
(`mirror` | `api` | `ttl-only`), `generator` (definition version) and
`truncated`.

- **Fingerprint** — a hash over the structure-bearing entries of the default
  branch: the blob SHAs of every manifest and convention file, the tree SHAs of
  the doc roots, ADR directories and `.github/workflows`, and the directory
  names to depth 2. A code commit that touches none of them leaves it
  unchanged; a doc edit, a new package or a renamed workflow changes it.
- **Refresh** — `scripts/profile.sh check` runs inside preflight whenever a
  review is due: `git ls-remote` on the default branch (tip equals `verified` →
  done), else a mirror fetch and a fingerprint compare. A mismatch, a profile
  older than 7 days, or a definition version change regenerates before the
  review starts. The history section is recomputed on every check.
- **Per-PR masking** — the worklist's `profile_slice` marks every row whose
  `src` the PR changes `verify_live: true`, and `structure_changed` lists the
  structure-bearing paths the PR touches. A `verify_live` row is a pointer to
  read the live file, not a fact.
- **Backstop** — the audit's `profile_fresh` check fails when the stored
  fingerprint no longer matches the default branch, the profile is older than 7
  days, or its `generator` is not the running definition version.
- **Notes** keep their own currency: a note's source blob changing marks it
  `stale`, a vanished source `orphan`.

## Mirror and fallbacks

The mirror is a bare, blob-less, depth-1 clone of the default branch under
`${TMPDIR:-/tmp}/code-guardian-mirror/<host>/<owner>/<repo>.git` — off the
shared home volume ([persistence.md](persistence.md)) — created under a `mkdir`
lock when missing, so a fresh pod rebuilds it on its first review. Tree
listings and file reads are local `git` calls; only the tip fetch touches the
network.

- Mirror unavailable (no `git`, clone or fetch failed) → the GitHub tree and
  contents API, capped at 80 reads per regeneration. A `truncated: true` tree
  answer disables the fingerprint: `mode: ttl-only`, refreshed daily.
- Remote unreachable → the stored profile is kept (`status: unverified`), or
  the run continues without one (`status: unavailable`).
- **The profile never gates a review.** Whatever its status, the pipeline runs
  exactly as without it.

## In the worklist

`profile` (run level): `{status, mode, base, verified, generated, age_hours,
truncated, file}` — `status` ∈ `current` | `regenerated` | `unverified` |
`unavailable` | `disabled`. Echo one line in the chat UI.

Per `reviews_due` entry, computed by `scripts/profile.sh slice` from the PR's
file list ([review.md](review.md) → **Per-PR review sequence** step b):

- `files[]` — `{path, status, class}` with `class` ∈ `code` | `test` | `docs` |
  `config` | `lockfile` | `snapshot` | `build` | `vendored` | `minified` |
  `sourcemap` | `generated`; `noise_count` counts the last seven classes.
- `profile_slice[]` — `{section, row, verify_live}` for the modules, docs,
  decisions, conventions, ownership and checks rows the PR touches.
- `structure_changed[]`, `history_slice[]` (the `## History` rows for the
  touched directories), and `memory_due[]` — the area-memory files whose scope
  the PR touches ([preferences.md](preferences.md) → **Route feedback by
  scope**).

`files_truncated: true` means the list stopped at 1 000 files — build the
changed-file list from the diff for that PR.

## Using it

- **Skill briefs** carry the path `work/PROFILE.md`, the PR's `verify_live`
  rows and `structure_changed` ([skills.md](skills.md) → **Invocation & audit
  log**), so a subagent reads the profile instead of mapping the repository.
- **The review** uses `profile_slice` and `history_slice` for orientation and
  priority — which module a hunk belongs to, which doc page covers it, where
  this repository's findings have clustered — and the `## Conventions` copy in
  place of reading the repository's own instruction files from the clone.
- **Notes** — `work/PROFILE-NOTES.md`, a table `| paths | note | src |` of at
  most 10 rows, two sentences each: what the map cannot state, such as a unit
  convention or a trap in one module. Written by the operator in the direct
  session, or by the audit run when a lesson generalizes to a code area
  ([audit.md](audit.md) task 30). The audit re-verifies `stale` rows against
  the live source and drops `orphan` ones.

## Configuration

`project_profile` in `work/CONFIG.md`: `enabled` (missing = enabled) |
`disabled`. Disabled → preflight emits `profile.status: disabled`, no mirror,
no slice; `files[]` are still classified with the built-in noise globs.

Operator commands (direct session):
`bash "$HOME/scripts/profile.sh" generate` rebuilds unconditionally; `check`
reports without changing anything when the profile is current.
